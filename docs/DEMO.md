# Демонстрация на занятии

## Подготовить до занятия

1. Выложить репозиторий в свой GitHub, проверить README, ветки и последний зелёный workflow.
2. На VM запустить `bash scripts/deploy-vm.sh IP 8080 --search` и проверить `/api/health` с другого устройства.
3. На компьютере открыть браузер и Electron, на телефоне — Android APK. Во всех клиентах использовать один IP VM.
4. Создать два аккаунта и войти на разных устройствах. Для браузеров использовать разные профили/приватное окно.
5. Убедиться, что порт доступен по учебной сети. Открыть терминал VM с `docker compose ps` и логами.

## Показать за 5–7 минут

1. GitHub: показать main/develop/feature-ветки, структуру и README. Объяснить, что клиент общий, сервер один.
2. В браузере создать публичный канал. На телефоне найти его и вступить.
3. Отправить сообщения с двух устройств и из Electron: они появляются без обновления страницы.
4. Ответить, отредактировать своё сообщение, найти его по тексту. На другом устройстве изменения тоже видны.
5. Создать приватный канал: он не отображается в поиске второго аккаунта. Вступить по коду приглашения.
6. Коротко отключить сеть второго клиента, отправить сообщение первым, вернуть сеть — история восстанавливается.
7. Запустить нагрузку:

```bash
npm run test:load -- --url=http://IP_VM:8080 --users=10 --messages=100 --concurrency=8 --rate=30
```

8. Показать `httpAccepted`, `httpFailed`, `websocketDelivered`, `missing` и p95. Успех — ошибки 0, missing 0. Затем посмотреть созданный канал «Нагрузка ...».
9. Перезапустить API: `docker compose restart api`; показать, что история не исчезла.

## Что сказать по устройству проекта

«Сообщение сначала проверяется и сохраняется в PostgreSQL, потом Socket.IO рассылает событие участникам канала. clientId защищает от повторной записи при сетевой ошибке. Клиент одинаковый: браузер, Capacitor на телефоне, Electron на компьютере. Redis нужен для обмена событиями между процессами. Elasticsearch — дополнительный поисковый индекс, исходные данные остаются в PostgreSQL».

## Если что-то не подключается

- Проверить `/api/health` именно с устройства, где возникла проблема.
- Проверить IP/порт, сеть, firewall и проброс NAT. На телефоне не использовать localhost.
- Проверить `ALLOWED_ORIGINS`, затем `docker compose up -d --force-recreate api`.
- Проверить логи `api`, `postgres`, `redis`; для поискового стека добавить `-f compose.yaml -f compose.search.yaml`.
- При 429 снизить `--rate`, либо поднять лимиты только для нагрузочного эксперимента.
- При проблемах поиска выполнить `search:reindex`.

## К следующему занятию

Поставить Node.js 24, Git и редактор; на VM — Docker/Compose; локально выполнить `npm ci`, `npm run dev`, на VM проверить доступ по IP. Для Android дополнительно Android Studio/JDK 21/SDK 36. Версии и параметры сервера уже закреплены в репозитории.
